1. `torchft/checkpointing/rdma_transport_test.py:834`, `torchft/checkpointing/rdma_transport_test.py:883`, `torchft/checkpointing/rdma_transport_test.py:1048`
The new Phase 2 locking tests stop at `_open_handshake()`, which only drives the TCP side channel through `_HANDSHAKE_READY` and then returns a raw socket. They never call `recv_checkpoint()`, so they do not exercise the actual receive path that is supposed to hold the sender-side reader fence until after `_read_control_record()`, `_read_manifest()`, `_read_tensors()`, and the final `_HANDSHAKE_DONE` in `recv_checkpoint()` (`torchft/checkpointing/rdma_transport.py:304-369`). A regression where the receiver sends `DONE` too early, skips it on some path, or otherwise mis-orders the handshake relative to the RDMA reads would still leave these tests green.

2. `torchft/checkpointing/rdma_transport_test.py:64-77`, `torchft/checkpointing/rdma_transport_test.py:126-144`
`_MockRdmaMemory` registers every buffer in a global `_registry`, but neither `_MockRdmaMemory` nor `_RDMAMockBase` ever unregisters or resets that registry. The mock therefore makes RDMA memory immortal across generation retirement and shutdown, while the production code is explicitly trying to validate that old snapshot generations become unreachable and get torn down. That means the Phase 2 lifecycle tests cannot catch stale-buffer reads or use-after-retirement mistakes: a read against an "old" remote buffer will continue to succeed in the mock long after the real implementation would have dropped the backing `RdmaMemory`.

3. `torchft/checkpointing/rdma_transport.py:607-636`, `torchft/checkpointing/rdma_transport_test.py:1438-1530`
The strided tests cover fresh-allocation round trips, but they do not cover the in-place receive path, which is the only receive-side path that actually depends on `_cast_tensor(target, torch.uint8)` before reconstructing the view with `torch.as_strided(...)`. Every Phase 3 strided test uses `receiver = self._new_transport()` with no `state_dict` callback, so a bug specific to preallocated non-contiguous destinations or DTensor locals would slip through even though zero-copy receive is a Phase 3 feature.
